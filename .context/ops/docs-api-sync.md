# Process ④ — Documentation / API-Surface Sync

> Process spec. Enforces the **additive-only public-API contract**.

## Toolchain (decided)

| Concern | Tool | Blocking? |
|---|---|---|
| Public API surface tracking | `@microsoft/api-extractor` (committed `etc/<pkg>.api.md`, CI diffs) | Block on drift |
| Export / type correctness | `publint` + `@arethetypeswrong/cli` (`--pack`) | Block |
| CHANGELOG | generated by `nx release` (Keep-a-Changelog shape), breaking/migration lines hand-written | Block on missing entry |
| Per-package README in tarball | one README per lib + `files` allowlist | Block (must be present) |
| API reference docs | TypeDoc for core (optional) | Advisory |

## API-surface tracking — `@microsoft/api-extractor`

Generates a canonical API report (`etc/<pkg>.api.md`) = pseudocode of every export. **Commit it.** CI
regenerates and diffs; a difference fails the build. A **removed** line = a breaking change / accidental
API removal caught before publish.

`api-extractor.json` per package:
```jsonc
{
  "mainEntryPointFilePath": "<projectFolder>/dist/index.d.ts",
  "apiReport": { "enabled": true, "reportFolder": "<projectFolder>/etc/" },
  "docModel": { "enabled": true },
  "dtsRollup": { "enabled": false }   // disable for the Angular pkg (rollup assumes single entry point)
}
```
```bash
api-extractor run --verbose   # CI: fail if committed etc/*.api.md drifted
api-extractor run --local     # locally: update the report, then commit it
```
**Policy:** if `etc/*.api.md` removed a line → require a major bump (pre-1.0: minor) + a `### Migration` block
in the new CHANGELOG entry.

## Export / type correctness (high priority: core=ESM, angular=CJS)

```bash
npm pack                                              # produce the exact artifact
npx publint                                           # audit package.json wiring
npx @arethetypeswrong/cli --pack . --profile esm-only # core
npx @arethetypeswrong/cli --pack . --profile node16   # angular
```
Both blocking — they catch "types say ESM but runtime is CJS" breakage that npm's own validation misses.

## Per-package README

npm shows the README **inside each package's tarball**, never the monorepo root README. So:
- One focused README per lib (`libs/<pkg>/README.md`); root README stays the GitHub landing page.
- **ng-packagr does NOT auto-copy README** → add it to `ng-package.json` `assets` (angular) / ensure the
  build copies it into `dist/` (core). Verify with `npm pack --dry-run` (README in file list).
- `files: ["dist", "README.md", "LICENSE.md"]` per lib.

## CHANGELOG + migration policy

- Format: Keep-a-Changelog (`Added/Changed/Deprecated/Removed/Fixed/Security`, newest-first, semver headings).
- Generated by `nx release` from Conventional Commits; **hand-write** the breaking/migration prose.
- Breaking change → in that version's entry add a `### Migration` subsection (old → new). No separate docs site.

## The docs gate (blocking unless noted)

- (a) CHANGELOG has an entry for the new version. **Block**
- (b) `api-extractor run` — no `etc/*.api.md` drift; removed line → major + migration. **Block**
- (c) `publint` + `attw --pack`. **Block**
- (d) README present in each tarball (`npm pack --dry-run`). **Block**
- (e) TypeDoc build. *Advisory*
- (f) Changelog prose / migration completeness (human review). *Advisory*

Wire blocking checks into each lib's `prepublishOnly` so they can't be skipped:
```jsonc
"scripts": {
  "check:api":   "api-extractor run --verbose",
  "check:pkg":   "publint",
  "check:types": "attw --pack . --profile esm-only",
  "prepublishOnly": "npm run build && npm run check:api && npm run check:pkg && npm run check:types"
}
```
